# Project Wiring Summary

## 1. System Overview

This system produces wrapped game executables with an in-game overlay. Two repositories collaborate through a strict separation of concerns:

| Repository | Role |
|------------|------|
| **Virule** (`wanderingme/virule`) | Admin tool, overlay UI, manifest generation, asset packaging, wrapper build pipeline |
| **SidecarK** (`wanderingme/SidecarK`) | Injection runtime, graphics API hooks, shared-memory frame compositor |

The single source of truth for runtime overlay configuration is **`manifest.json`**, generated by Virule's build process and consumed by the Overlay UI at runtime.

---

## 2. Repository Responsibilities

### 2.1 Virule Owns

- **Game metadata authoring** — publishers, developers, game records (stored under `internal/games/<gameId>/game.json`).
- **Overlay content authoring** — feed, troubleshooting, promotional/spotlight data (stored under `internal/games/<gameId>/overlay/`).
- **`manifest.json` generation** — `virule::app_data::prepare_wrapper_manifest()` assembles game metadata, overlay JSON sections, asset references, and build exe path into a single manifest written atomically to `<staged>/.virule/manifest.json`.
- **Asset packaging** — referenced images are copied into `.virule/assets/` alongside the manifest.
- **Wrapper build pipeline** — `virule::app_data::stage_build()` stages the game directory, invokes `virule::wrapper_model::write_wrap_payload()` to produce a binary payload appended to the wrapper stub, and validates the result via `check_wrapper_ready()`.
- **Overlay UI source** — React + Vite application under `overlay_ui/`, built to `overlay_ui/dist/` with `base: "./"` for local file loading.

### 2.1.1 SidecarK Runtime Artifacts Packaged by Virule

Virule carries the SidecarK runtime binaries inside the repo so the **Admin “Validate & Build”** step can package the correct architecture alongside the wrapped game.

**Canonical repo location (Virule):**

```
virule/assets/sidecark/
  Win32/
    SidecarKHost.exe
    SidecarK32.dll
  x64/
    SidecarKHost.exe
    SidecarK64.dll
```

Notes:

- `SidecarKHost.exe` is named the same in both architecture folders.
- The injected DLL name is architecture-specific: `SidecarK32.dll` vs `SidecarK64.dll`.
- The build pipeline must select the folder matching the target game bitness and stage those binaries into the final wrapped output.

### 2.2 Virule Must NOT Own

Injection logic, graphics hooks, frame compositing, in-process rendering hooks.

### 2.3 SidecarK Owns

- **Injection** — CBT hook-based global injection (`SKX_InstallCBTHook`, `CBTProc`) via `rundll32.exe`-hosted DLL.
- **Graphics API hooks** — DXGI/D3D11 swap chain Present hook (`IWrapDXGISwapChain::Present`), D3D12 present path, OpenGL `SwapBuffers` hook.
- **Shared-memory frame mapping** — `SidecarKHost` creates and owns `Local\SidecarK_Frame_v1_<pid>` with SKF1 v1 header. Consumer (injected DLL) opens the mapping read-only; producer (external process) opens write-only.
- **Overlay compositing** — on each Present call, the injected consumer reads SKF1 pixel data via stable-read protocol, uploads to a GPU texture, and blits onto the game backbuffer via `CopySubresourceRegion` (D3D11) or equivalent.
- **Control plane** — named pipe `\\.\pipe\SidecarK_Control_<pid>` and shared memory `Local\SidecarK_Control_<pid>` for overlay on/off toggle.

### 2.4 SidecarK Must NOT Own

Content authoring, game metadata, overlay business logic, packaging/build pipeline.

## 3. Artifact: `manifest.json`

### 3.1 Generation

`prepare_wrapper_manifest()` in `src/core/app_data.cpp`:

1. Loads the game record by ID.
2. Computes a relative exe path (omitting `install_folder`).
3. Reads overlay JSON files (`feed.json`, `troubleshooting.json`, `description.txt`) from the game's overlay directory.
4. Assembles spotlight/promotional items from selected slide IDs.
5. Writes the complete manifest to `<staged_latest>/.virule/manifest.json` atomically.

### 3.2 Schema

```json
{
  "game": { "id", "title", "steam_app_id", "description", ... },
  "publishers": [...],
  "developers": [...],
  "assets": { "game_box_art", "publishers": {}, "developers": {} },
  "overlay": {
    "feed": { "items": [...] },
    "troubleshooting": { "sections": [...] },
    "promotion": { "items": [...] }
  },
  "build": { "exe_path": "<relative>" }
}
```

### 3.3 Location in Built Output

```
<gameSlug>/
  .virule/
    manifest.json
    index.html        (overlay UI entry point)
    static/           (Vite build output)
    assets/           (images referenced by manifest)
```

## 4. Current State

### 4.1 Virule — Wrapper Runtime (Temporary)

The wrapper runtime (`src/wrapper_runtime/wrapper_runtime.cpp`) currently:

1. Reads the embedded binary payload appended to its own exe.
2. Extracts `.virule/` contents (including `manifest.json`, `index.html`, static assets) to a local cache under `%LOCALAPPDATA%\Virule\overlay_cache\<game_id>\<build_key>\`.
3. Extracts the original game exe to the wrapper directory.
4. Launches the game process via `CreateProcessW`.
5. Hosts the overlay in a **WebView2** window (`CreateCoreWebView2EnvironmentWithOptions`) as a WS_EX_TOPMOST popup.
6. Navigates WebView2 to `file:///<cache>/.virule/index.html`.
7. Toggles overlay with a global hotkey; **suspends** the game process while overlay is visible.
8. On game exit, cleans up overlay and terminates.

**Key limitation**: This is an out-of-process, non-composited overlay. The game is frozen while the overlay is shown. There is no SidecarK integration.

### 4.2 Overlay UI

- `overlay_ui/src/runtime/manifest.ts`: checks `window.__VIRULE_MANIFEST__` first (for host injection), falls back to `fetch("/manifest.json")`.
- `overlay_ui/src/types.ts`: defines `Manifest`, `FeedItem`, `PromoItem`, `TroubleshootItem`, `TroubleshootSection`.
- `overlay_ui/src/ui/App.tsx`: renders game overview, feed player, promotional carousel, troubleshooting FAQ — all driven entirely by manifest data.
- `overlay_ui/src/runtime/externalLinks.ts`: supports `window.__VIRULE_OPEN_URL__` bridge for native link-out.
- Vite config uses `base: "./"` and `assetsDir: "static"` for local file loading.

### 4.3 SidecarK

- Fully operational V1 injection and compositing runtime.
- `SidecarKHost` (the host process) creates the SKF1 shared memory mapping, injects SidecarK DLL into the target game, and manages lifecycle.
- The injected DLL hooks Present and composites overlay frames from shared memory onto the game backbuffer.
- SKF1 protocol is frozen: header at offset 0x00–0x23, `frame_counter` at 0x20, pixel data at 0x24. BGRA8 format. Stable-read semantics enforced.
- Validated on DXGI/D3D11. Experimental on D3D12 and OpenGL.
- **Does NOT currently host any UI surface producer.** Phase 3 (connecting a real producer) has not been implemented.
- **Is NOT integrated with Virule's wrapper output.**

## 5. Target Architecture

### 5.1 End-State Flow

```
[Virule Admin]
    │
    ▼
[stage_build()] ──► Wrapped EXE (wrapper stub + payload)
    │                  └── .virule/
    │                        ├── manifest.json
    │                        ├── index.html + static/
    │                        └── assets/
    ▼
[User runs wrapped EXE]
    │
    ├──► Wrapper extracts payload
    ├──► Wrapper launches SidecarKHost with target PID
    │       └── SidecarKHost creates SKF1 mapping
    │       └── SidecarKHost injects SidecarK DLL into game
    ├──► Wrapper launches CEF subprocess (producer)
    │       └── CEF loads .virule/index.html
    │       └── CEF reads manifest.json
    │       └── CEF renders overlay to offscreen BGRA surface
    │       └── Producer opens SKF1 mapping (OpenFileMappingW)
    │       └── Producer writes BGRA frames + increments frame_counter
    ├──► Game runs normally
    │       └── SidecarK DLL hooks Present
    │       └── Consumer reads SKF1 frames (stable-read)
    │       └── Consumer blits overlay onto backbuffer
    └���─► On game exit: wrapper signals shutdown to all subprocesses
```

### 5.2 Integration Points

#### Wrapper → SidecarKHost Discovery

The wrapper must locate `SidecarKHost.exe` at a known relative path within the built output (or a registered install path). The wrapper launches SidecarKHost, passing the game's target PID. SidecarKHost creates the SKF1 mapping named `Local\SidecarK_Frame_v1_<pid>` and injects the DLL.

**Virule packaging source-of-truth (repo):** `virule/assets/sidecark/{Win32|x64}/...` (see §2.1.1).

**Wrapped output expectation:** the Admin “Validate & Build” step stages the matching `SidecarKHost.exe` + (`SidecarK32.dll` or `SidecarK64.dll`) into the wrapped game output.

#### manifest.json Location

Resides at `.virule/manifest.json` within the extracted overlay cache. The CEF producer reads it from this path. At no point does SidecarK itself read or interpret `manifest.json` — it is consumed exclusively by the Overlay UI running inside CEF.

#### CEF Loading

CEF replaces WebView2. The producer subprocess launches CEF in offscreen rendering mode, navigates to `.virule/index.html`, and injects `window.__VIRULE_MANIFEST__` with the parsed manifest (or lets the UI fetch it via relative path). CEF's offscreen render callback delivers BGRA pixel buffers.

#### Frame Pipeline Contract

| Property | Value |
|----------|-------|
| Mapping name | `Local\SidecarK_Frame_v1_<pid>` |
| Header format | SKF1 v1 (0x24 bytes) |
| Pixel format | BGRA8 (pixel_format=1) |
| Mapping owner | SidecarKHost (CreateFileMappingW) |
| Producer access | OpenFileMappingW only; fail fast if absent |
| Write order | Pixels first → memory barrier → increment frame_counter |
| Consumer read | Stable-read: read c1, copy pixels, read c2, accept iff c1==c2 && c1≠0 |
| Staleness | Consumer retains last valid frame; never blanks |
| Max dimensions | Defined by host allocation (kSKF1_MaxWidth × kSKF1_MaxHeight × 4 bytes) |

#### Control Plane

SidecarKHost exposes `\\.\pipe\SidecarK_Control_<pid>` for overlay on/off commands. The wrapper (or a control client) sends `overlay on\n` / `overlay off\n`. The control client must never touch the SKF1 mapping.

### 5.3 Lifecycle Ownership

| Event | Owner |
|-------|-------|
| Launch game process | Wrapper |
| Launch SidecarKHost | Wrapper |
| Create SKF1 mapping | SidecarKHost |
| Inject DLL into game | SidecarKHost |
| Launch CEF producer | Wrapper |
| Open SKF1 mapping | CEF producer |
| Write overlay frames | CEF producer |
| Composite frames into game | SidecarK DLL (injected) |
| Toggle overlay visibility | Wrapper → control pipe → SidecarKHost |
| Game exit detection | Wrapper (WaitForSingleObject on game process handle) |
| Shutdown CEF producer | Wrapper (signal or terminate) |
| Release SKF1 mapping | SidecarKHost (on shutdown) |
| Shutdown SidecarKHost | Wrapper (signal or terminate) |

### 5.4 Error Handling Expectations

| Boundary | Expectation |
|----------|-------------|
| SKF1 mapping absent when producer starts | Producer fails fast; wrapper retries or reports error |
| Producer crashes mid-stream | Consumer retains last valid frame; no crash propagation |
| SidecarKHost fails to inject | Wrapper detects failure, falls back or reports error; game may run without overlay |
| Game exits unexpectedly | Wrapper detects process exit, signals shutdown to SidecarKHost and producer |
| CEF fails to render | Producer stops advancing frame_counter; consumer shows last good frame |
| Control pipe unavailable | Wrapper logs error; overlay toggle unavailable but game continues |

## 6. What Must Change

| Component | Current | Target |
|-----------|---------|--------|
| Wrapper overlay host | WebView2 (out-of-process popup, game suspended) | CEF offscreen (in-pipeline, game runs continuously) |
| Wrapper → SidecarK coordination | None | Wrapper launches SidecarKHost, passes target PID |
| Overlay frame delivery | WebView2 renders directly to screen | CEF renders to BGRA buffer → SKF1 shared memory → compositor blits to backbuffer |
| manifest.json consumer | WebView2 navigates to file URI | CEF loads same file URI or injects via `__VIRULE_MANIFEST__` |
| Game process during overlay | Suspended (NtSuspendProcess) | Runs normally; overlay composited in Present hook |
